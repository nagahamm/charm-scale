# 要件定義書

このドキュメントは charm-scale の要件を BDD(振る舞い駆動開発)寄りのシナリオ形式でまとめたものである。実装済みの機能は対応する Issue 番号を添える。新規機能から着手する際は、まずこのドキュメントにシナリオを追記してから実装に入る。

## 1. 目的・背景

マッチングアプリの会話・プロフィール写真・プロフィール文を AI に読ませ、利用者自身の振る舞いを客観視して改善できるようにする。改善対象は常に利用者自身であり、相手を操作・評価する道具にはしない([CLAUDE.md](../CLAUDE.md) Safety 制約)。

## 2. 用語(ドメイン用語集)

| 用語 | 定義 |
| :--- | :--- |
| User | このアプリのアカウントを持つ利用者本人 |
| Person | User がやり取りしている相手(マッチング相手)。User が任意のニックネームで管理する |
| Analysis | 1回の解析結果。会話モード or 写真モードのいずれか。Person に紐づく |
| Timeline entry | 会話モードの Analysis に含まれる、吹き出し1件分の再現データ |
| Rewrite / MessageCritique | 「もっとこうすべきだった」の添削(原文・問題点・改善文・理由) |
| Photo evaluation | 写真モードの Analysis に含まれる、写真1枚ごとの評価 |
| Positioning | いいね数から見た大まかな立ち位置の目安(AIによる推定、実データではない) |

## 3. 実装済み機能(シナリオ)

### 3.1 会話モード(#2, #3, #6)

```gherkin
Feature: 会話スクリーンショットの分析

  Scenario: 会話スクショだけで分析する
    Given トーク画面のスクリーンショットを1〜8枚選んでいる
    When 「分析する」を押す
    Then 食いつき度数(0-100)・会話フェーズ・項目別スコア(返信速度/文量バランス/質問返し/感情表現/主導権)が表示される
    And 送った文のうち損をしているものには、タップで開ける改善案(問題点・改善文・理由)が添削として付く
    And 実際のトーク画面のような吹き出し形式で会話が再現される
    And 次に送るべき返信案がトーン違いで2〜3案提示される

  Scenario: 相手のプロフィールも合わせて分析する
    Given 会話スクショに加えて、同じ相手のプロフィール画面のスクショを追加している
    When 「分析する」を押す
    Then 年齢・職業・いいね数・自己紹介の要約・プロフィール項目一覧・興味タグが表示される
    And 次の返信案は、プロフィールの話題を自然に絡めたものになりうる

  Scenario: 複数枚のスクショが時系列順でない
    Given 会話スクショを実際の時系列とは異なる順序でアップロードしている
    When 「分析する」を押す
    Then 日付区切り・時刻・受け答えの整合性から実際の時系列を判断し、正しい順序で分析される

  Scenario: 相手からの返信が一件もない
    Given 自分の発言だけが続いているスクショをアップロードしている
    When 「分析する」を押す
    Then その旨が要約に明記され、存在しないやり取りは捏造されない
```

### 3.2 写真モード(#2, #4, #5)

```gherkin
Feature: プロフィール写真の分析

  Scenario: 自分の写真だけを評価する
    Given 評価したい写真を1〜8枚(1枚目がメイン写真)選んでいる
    When 「分析する」を押す
    Then 総合スコアと、第一印象・全体印象の一貫性の2項目が表示される
    And 写真ごとに(メイン写真バッジ付きで)個別のサムネイル・被写体カテゴリ・スコア・コメントが表示される
    And 被写体が人物でない写真(風景・食事・ペットなど)は、それぞれの観点で評価される
    And 撮り直しが必要な写真には、その写真固有の具体的な指示が付く

  Scenario: 自分のプロフィール文も合わせて評価する
    Given 写真に加えて、自分のプロフィール画面のスクショを追加している
    When 「分析する」を押す
    Then 自己紹介文の添削(原文・問題点・改善文・理由)が表示される
    And 画面上にいいね数が読み取れた場合、公開調査データを根拠にした大まかな立ち位置の目安が、出典タグ付きで表示される(実データではないことを明記)
```

### 3.3 人別の履歴(#13, #15, #16)

対象は会話モードのみ(写真モードは相手を持たない)。

```gherkin
Feature: 相手ごとの分析履歴

  Scenario: 分析する相手を選ぶ
    Given 会話モードを選んでいる
    When 「相手を選択」から相手を選ぶ(その場で新しい相手を追加することもできる)
    Then 分析結果はその相手の履歴として保存される
    And 相手を選ぶまで「分析する」は押せない

  Scenario: 相手一覧を開く
    Given これまでに複数の相手を分析している
    When 「相手一覧」を開く
    Then 相手ごとのカード(ニックネーム・最新の食いつき度数・会話フェーズ・直近の見出し)が並ぶ
    And まだ分析がない相手には「まだ分析がありません」と表示される

  Scenario: 同じ相手の分析が積み上がる
    Given ある相手に対して複数回分析している
    When その相手のカードをタップする
    Then 過去の分析が新しい順に一覧できる
    And いずれかをタップすると、当時の分析結果を分析時と同じ画面で読み返せる

  Scenario: 食いつき度数の推移を見る
    Given ある相手に対して複数回分析している
    When その相手の履歴を開く
    Then 食いつき度数の推移が分析をまたいで古い順にグラフで見られる
    And グラフの両端に、最初と最新の分析日が表示される
    And 分析が1回しかない場合、推移は表示されない(点が1つでは推移にならないため)

  Scenario: 続きのスクショで分析を更新する
    Given ある相手の履歴を開いている
    When 「続きのスクショで分析」から、その後のやり取りのスクショを送る
    Then 直前の分析の要約を引き継いだ続きとして解析される
    And その相手の新しい分析として履歴に積み上がり、推移グラフにも反映される
    And 引き継ぐ内容(前回の要約)は、送信する前に画面上で確認できる
    And まだ分析が1件もない相手には、この導線は現れない

  Scenario: 相手の削除
    Given ある相手の履歴が不要になった
    When その相手を削除する
    Then 紐づく分析もすべて削除される(相手の個人情報を持ち続けない)

  Scenario: ログインしていない
    Given ログインしていない
    When アプリを使う
    Then 相手一覧は表示されず、分析結果も保存されない(その場で結果を見るだけになる)
```

### 3.4 利用回数の制限(#14)

```gherkin
Feature: 1日の解析回数の制限

  Scenario: 上限に達していない
    Given その日の解析回数がまだ上限に達していない
    When 分析を実行する
    Then これまで通り解析され、その日の残り回数が1回分減る

  Scenario: 1日の解析回数上限に達する
    Given その日にすでに上限回数まで解析している
    When さらに分析しようとする
    Then 上限に達している旨(上限回数を含む)のエラーが表示され、解析は実行されない(Claude APIコストの制御)
    And 日付(日本時間)が変わると再び解析できるようになる

  Scenario: 解析が失敗した場合
    Given 分析を実行したが、解析が最後まで完了せずエラーになった
    When その日の残り回数を確認する
    Then 失敗した分は回数として消費されていない

  Scenario: 会話・写真・下書きチェックのいずれも同じ枠を使う
    Given その日に会話モードで分析している
    When 写真モードや「この文をチェックする」を実行する
    Then それらも同じ1日の上限枠を消費する(いずれもAIの解析を伴うため)
```

> 上限回数は運営側の設定値(環境変数)であり、利用者が変更することはできない。ログインしていない状態(サーバー側でアカウントを特定できない構成)では回数を数えられないため、この制限は適用されない。

### 3.5 アカウント(#7, #17)

```gherkin
Feature: アカウント登録・ログイン

  Scenario: メールアドレスで登録する
    Given アプリを初めて起動した
    When メールアドレスとパスワードでアカウントを作成する
    Then ログイン状態になり、以後の分析結果が自分のアカウントに保存される

  Scenario: Google または Apple でログインする
    Given アプリを初めて起動した
    When 「Googleで続ける」または「Appleで続ける」を選ぶ
    Then パスワードを設定することなくログイン状態になる

  Scenario: 新規登録数の上限に達している
    Given 運営が定めた新規登録者数の上限に達している
    When ログイン画面を開く
    Then 新規登録の受付を停止している旨と、空きが出た際の案内が表示される
    And 新規登録は実行できない

  Scenario: 上限に達していても既存のアカウントは使える
    Given 新規登録の受付が停止している
    And すでにアカウントを持っている
    When ログインする
    Then これまで通りログインでき、機能に制限はかからない
```

> 上限値は運営側の設定値であり、利用者が変更することはできない。設定が未投入・確認に失敗した場合は登録を許可する(締め出しの事故を避けるため)。

```gherkin
Feature: 全 Person 横断のフィードバック

  Scenario: 自分の傾向を俯瞰する
    Given 複数の Person に対する Analysis が蓄積している
    When 「全体フィードバック」を開く
    Then 項目別スコアの平均・推移など、自分の会話・写真の傾向が横断的に表示される
```

### 4.2 返信案のチェック(会話モードの拡張)

> プロトタイプで操作フローを確定済み。バックエンドのスキーマ拡張・実装はこれから。

```gherkin
Feature: 会話の再現画面での返信案チェック

  Scenario: 添削付きメッセージから複数の返信案を選ぶ
    Given 会話の再現画面で、添削(rewrite)付きの自分の発言をタップしている
    Then その場に問題点と、複数(2件程度)の返信案候補が展開される
    And 候補をタップするとコピー済み表示に切り替わる

  Scenario: 次に送る返信案からコピーする
    Given 「次に送る返信案」の候補カードを見ている
    When カードをタップする
    Then その文面がコピーされ、コピー済み表示に切り替わる

  Scenario: 自分で書いた下書きをチェックする
    Given これから送ろうとしている文を入力欄に入れている
    When 「この文をチェックする」を押す
    Then 別の言い方の候補が複数提示され、タップでコピーできる
    And 想定される相手の反応が、断定しない定性的な表現(例:「前向きな返信が期待できそう」)で示される
    And 参考として、想定される相手からの返信例が「AIによる予測」と明示された吹き出しで表示される
    And 数値的な確率(例: 「95%の確率で好意的」)は表示しない。単一の推論に対して精度を保証できる数値ではないため
```

## 5. 非機能要件

- **プライバシー**: スクリーンショット画像はサーバー・DBのどこにも保存しない(現状維持。Rawログにも画像は含めない)。永続化するのは構造化された解析結果(テキスト)のみ。Person に紐づく相手の情報(年齢・職業・自己紹介の要約など)は第三者の個人情報であるため、User が Person を削除すれば紐づく全データを削除できること。
- **Safety**: 相手を操作・強要する助言を返さない。改善対象は常に利用者自身(現状維持)。
- **モデル**: `claude-opus-5` を使用し、Structured Outputs でスキーマに固定する(現状維持)。
- **ストリーミング**: NDJSON ストリーミングは維持し、関数のタイムアウトを回避する(現状維持)。
- **データ整合性**: AIの出力はまず Raw ログとして非同期で保存し、アプリが実際に使うデータはスキーマ検証(Zod)を通してから正規化DBへ保存する二重化構成にする([design.md](./design.md) 1.1節)。検証に失敗しても Raw ログは残るため、データそのものは失われない。

- プッシュ通知

- LINEログイン(Supabase Auth に標準搭載されておらず、カスタムOIDCの設定と LINE Developers での手作業が必要。Google / Apple で足りるため扱わない)
